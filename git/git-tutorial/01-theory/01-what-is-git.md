# Git이란?

## 📌 버전 관리 시스템 (VCS)

**Git**은 소스 코드의 변경 이력을 추적하고 관리하는 **분산 버전 관리 시스템**입니다.

### 버전 관리가 필요한 이유

개발 과정에서 다음과 같은 상황을 경험해본 적이 있나요?

```
프로젝트_최종.zip
프로젝트_최종_진짜최종.zip
프로젝트_최종_진짜진짜최종.zip
프로젝트_최종_이번엔진짜.zip
```

버전 관리 시스템은 이런 문제를 해결합니다:

- ✅ **변경 이력 추적**: 누가, 언제, 무엇을, 왜 변경했는지 기록
- ✅ **이전 버전으로 복구**: 문제가 생기면 과거 시점으로 돌아가기
- ✅ **협업 지원**: 여러 개발자가 동시에 작업 가능
- ✅ **브랜치 관리**: 독립적인 작업 공간 생성
- ✅ **백업**: 코드의 안전한 보관

## 🌟 Git의 특징

### 1. 분산 버전 관리
- 중앙 서버뿐만 아니라 각 개발자의 로컬에도 전체 저장소가 존재
- 네트워크 없이도 대부분의 작업 수행 가능
- 서버 장애 시에도 작업 지속 가능

### 2. 빠른 성능
- 대부분의 작업이 로컬에서 수행
- 효율적인 데이터 구조 사용

### 3. 데이터 무결성
- 모든 데이터는 체크섬(SHA-1 해시)으로 관리
- 데이터 손실이나 변조 방지

### 4. 브랜치 시스템
- 가볍고 빠른 브랜치 생성/전환
- 실험적 개발과 안정적 개발 분리

## 🔄 Git vs 기타 VCS

### 중앙 집중식 (SVN, CVS)
```
        [중앙 서버]
           |
    +------+------+
    |      |      |
  개발자1 개발자2 개발자3
```
- 모든 작업이 중앙 서버와 통신 필요
- 서버 장애 시 작업 불가

### 분산식 (Git, Mercurial)
```
[원격 저장소]
    |
    +-------------------+
    |         |         |
[로컬 저장소1] [로컬 저장소2] [로컬 저장소3]
    |         |         |
  개발자1    개발자2    개발자3
```
- 각 개발자가 전체 저장소 보유
- 오프라인 작업 가능
- 빠른 속도

## 📂 Git의 기본 개념

### 저장소 (Repository)
프로젝트의 모든 파일과 변경 이력을 저장하는 곳

- **로컬 저장소**: 개발자의 컴퓨터에 있는 저장소
- **원격 저장소**: GitHub, GitLab 등 서버에 있는 저장소

### 커밋 (Commit)
변경 사항의 스냅샷(저장 시점)

```
커밋1 → 커밋2 → 커밋3 → 커밋4
(초기)  (기능A) (수정)  (기능B)
```

### 브랜치 (Branch)
독립적인 작업 공간

```
        main: O → O → O → O
                    ↘
        feature:     O → O
```

## 🎯 Git을 사용하는 이유

1. **업계 표준**: 대부분의 IT 기업에서 사용
2. **오픈소스**: 무료로 사용 가능
3. **강력한 커뮤니티**: 풍부한 학습 자료와 지원
4. **GitHub/GitLab**: 협업 플랫폼과 완벽한 통합
5. **취업 필수 스킬**: 개발자 채용 시 기본 요구사항

## 🔍 Git의 작동 원리 (간단히)

Git은 파일의 변경사항을 추적합니다:

1. **작업 디렉토리**: 실제 파일들이 있는 곳
2. **스테이징 영역**: 커밋할 변경사항을 준비하는 곳
3. **저장소**: 커밋된 변경사항이 저장되는 곳

```
작업 디렉토리  →  스테이징 영역  →  로컬 저장소  →  원격 저장소
 (편집)       (git add)      (git commit)   (git push)
```

## 💡 핵심 요약

- Git은 **분산 버전 관리 시스템**
- **변경 이력 추적**과 **협업**이 핵심 기능
- **로컬 저장소**와 **원격 저장소**로 구성
- **커밋**으로 변경사항을 저장
- **브랜치**로 독립적인 작업 수행
